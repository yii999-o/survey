## 5.1 测试环境

| 项 | 值 |
| --- | --- |
| 操作系统 | Windows NT 10.0.26200（Windows 11 25H2） |
| Node.js | v24.21.0 |
| MongoDB | 9.0.2（测试时由助手启动独立临时实例） |
| 测试框架 | Jest 29.7.0 + Supertest 7.3.1 |
| 运行方式 | `pnpm test`（即 `jest --runInBand --detectOpenHandles`） |

测试助手 `tests/helpers/db.js` 会：

1. 查找本机 `mongod`（默认常见安装路径，或 `MONGOD_BINARY`）；
2. 用临时目录和随机端口启动一个独立 mongod；
3. 连接测试数据库；
4. 每个测试前清空集合；
5. 测试结束断开连接、结束进程、清理临时目录。

因此测试不会写入开发库 `survey_app`。

## 5.4 关键用例明细

### T01 创建问卷

- **步骤**：注册用户 → `POST /api/surveys`，body 含标题。
- **输入**：`{ "title": "课程反馈" }`，携带 Bearer token。
- **期望输出**：HTTP 201；`status=draft`；`shareCode` 为 12 位十六进制；`publicUrl` 含 `/survey/`；`ownerId` 存在。
- **结果**：通过。

### T02 添加题目

- **步骤**：创建草稿 → `PUT /api/surveys/:id`，提交 4 道题。
- **输入**：单选 q1、多选 q2、文本 q3、数字 q4。
- **期望输出**：HTTP 200；`questions.length=4`；`order` 从 0 递增；再次 GET 详情题目一致。
- **结果**：通过。

### T03 用户隔离

- **步骤**：A、B 各注册并各建一份问卷 → A 调 `GET /api/surveys`；B 调 `GET /api/surveys/:idA`。
- **期望输出**：A 的列表只含自己的 1 份；B 读取 A 的问卷返回 404。
- **结果**：通过。

### T04 发布空问卷被拒绝

- **步骤**：创建无题草稿 → 调 `POST /:id/publish`。
- **期望输出**：HTTP 400；错误信息包含“至少需要一道题目”。
- **结果**：通过。

### T05 发布并锁定题目

- **步骤**：添加题目 → 发布 → 再次 `PUT` 带 `questions`。
- **期望输出**：发布返回 `published` 和分享码；公开接口可读；再次改题返回 HTTP 409。
- **结果**：通过。

### T06 关闭问卷

- **步骤**：发布 → `POST /:id/close` → 访问公开链接。
- **期望输出**：关闭成功 `status=closed`；公开接口返回 HTTP 410。
- **结果**：通过。

### T07 截止时间已过

- **步骤**：创建 `deadline` 为 1 分钟前的问卷 → 添加题目 → 发布。
- **期望输出**：HTTP 400，错误包含“截止时间已过”。
- **结果**：通过。

### T08 单选题跳转

- **步骤**：q1 选项 A 配置 `goto: q3`；分别提交 q1=A、q1=B。
- **输入**：`{answers:[{qid:"q1",value:"A"}]}`。
- **期望输出**：A 的路径为 `[q1,q3,q4]`；B 的路径为 `[q1,q2,q3,q4]`；被跳过的 q2 不要求必答。
- **结果**：通过。

### T09 多选题跳转

- **步骤**：q1 多选配置 `includes:"C"`，提交 `["A","C"]` 与 `["A","B"]`。
- **期望输出**：前者跳过 q2；后者进入 q2。
- **结果**：通过。

### T10 数字题跳转与规则顺序

- **步骤**：分数题配置两条规则：`>=60 → q3`、`>=0 → q2`；分别提交 80、30。
- **期望输出**：80 的路径为 `[q1,q3]`；30 的路径为 `[q1,q2,q3]`。
- **结果**：通过。

### T11 跳转定义非法

- **步骤**：配置 `goto` 指向不存在的 q9，或指向当前题/前面的题。
- **期望输出**：保存/发布返回 400；错误包含“目标题目不存在”或“只能跳到后面的题目”。
- **结果**：通过。

### T12 路径外答案被拒绝

- **步骤**：q1=A 跳过 q2，但请求同时提交 q2 的答案。
- **期望输出**：HTTP 400；错误包含“已被跳转跳过，不能作答”。
- **结果**：通过。

### T13 跳过的必答题不校验

- **步骤**：q1=A 跳到 q3；q2 设为必答但不提交。
- **期望输出**：提交成功 201；`visitedPath=[q1,q3]`。
- **结果**：通过。

### T14 必答题缺失

- **步骤**：q1=B 进入 q2；q2 为必答但不提交。
- **期望输出**：HTTP 400；错误包含 q2 标题。
- **结果**：通过。

### T15 多选数量限制

- **步骤**：min=2、max=3，提交 1 个、2 个、4 个。
- **期望输出**：1 个 → “至少选择 2 个”；2 个 → 201；4 个 → “最多选择 3 个”。
- **结果**：通过。

### T16 文本长度

- **步骤**：minLength=2、maxLength=5，提交 1 字、3 字、6 字、emoji。
- **期望输出**：1 字失败；3 字成功；6 字失败；3 个 emoji 按 3 个字符计成功。
- **结果**：通过。

### T17 数字范围与整数

- **步骤**：min=0、max=120、integerOnly，提交 0、25、25.5、-1、130。
- **期望输出**：0、25 成功；25.5 “需为整数”；-1、130 范围错误。
- **结果**：通过。

### T18 匿名/登录限制

- **步骤**：`allowAnonymous=false` 的已发布问卷，无 token 提交；再带 token 提交。
- **期望输出**：无 token 401；带 token 201，且 `respondentId` 等于当前用户。
- **结果**：通过。

### T19 重复填写限制

- **步骤**：`allowMultiple=false`，同一登录用户提交两次。
- **期望输出**：第一次 201；第二次 409，错误包含“不允许重复填写”。
- **结果**：通过。

### T20 统计聚合

- **步骤**：提交 3 份答卷：q1 A/A/B，q2 [A]/[A,B]/[B]，年龄 20/30/40，文本 hi/yo/ok。
- **期望输出**：`totalResponses=3`；q1 A=2/B=1；q2 A=2/B=2/C=0；平均 30；min=20、max=40；文本列表 3 条。
- **结果**：通过。

### T21 单题统计

- **步骤**：`GET /api/surveys/:id/stats?qid=q1`。
- **期望输出**：`questions.length=1`，qid=q1，`totalResponses` 仍为 3。
- **结果**：通过。

### T22 空数据统计

- **步骤**：发布问卷但不提交，查看 q3 数字题。
- **期望输出**：`totalResponses=0`；`average=null`；`values=[]`。
- **结果**：通过。

### T23 越权查看统计/答卷

- **步骤**：用户 B 请求 A 的 `/stats` 与 `/responses/survey/:id`。
- **期望输出**：均返回 404。
- **结果**：通过。

### T24 删除草稿

- **步骤**：创建草稿 → `DELETE /api/surveys/:id`。
- **期望输出**：200 `{ok:true}`；列表为空。
- **结果**：通过。

### T25 发布后改说明

- **步骤**：发布后 `PUT` 只提交 `title/description`。
- **期望输出**：200，标题更新，题目不变。
- **结果**：通过。

## 5.5 UI 验收用例（浏览器）

除了接口测试，项目提供 `scripts/e2e-ui.js`：使用本机 Chrome/Edge 的 headless 模式，验证真实页面交互。它不需要下载浏览器，运行前需启动应用并执行 `pnpm seed`。

```bash
pnpm start          # 终端 1
pnpm test:e2e      # 终端 2（需要 Chrome 或 Edge；可用 CHROME_PATH 指定）
```

脚本会：

- 登录 `demo / demo123`，检查“我的问卷”和统计页；
- 在编辑页新建问卷、保存、发布，检查发布后题目锁定；
- 打开演示问卷，选择“使用过”，验证第 2 题隐藏、第 3/4/5 题可见；
- 填写并提交，验证成功提示；
- 空提交，验证必答错误提示；
- 创建一份“要求登录”的问卷，未登录访问，验证只显示登录提示；
- 结束后通过 MongoDB 清理自己创建的测试问卷/答卷，保持 demo 数据干净。

截图输出到 `docs/screenshots/`。

### M01 登录/我的问卷

1. 打开 `/login.html`；
2. 输入 `demo` / `demo123`，点击登录；
3. 期望进入 `/dashboard.html`，显示“我的问卷”和演示问卷。

### M02 新建/编辑/发布

1. 点击“+ 新建问卷”；
2. 填写标题、勾选“允许匿名填写”；
3. 添加单选题，填写题干和两个选项；
4. 保存，提示“已保存”；
5. 发布，提示“发布成功”，显示题目锁定提示和公开链接。

### M03 跳转与填写

1. 打开 `/survey/democode0001`；
2. 初始第 2 题可见；
3. 选择“使用过”，第 2 题应隐藏，第 3/4/5 题显示；
4. 填写多选、数字、文本，提交，显示“提交成功”和答卷编号。

### M04 前端校验

1. 打开演示问卷，不填必答题直接提交；
2. 期望出现“为必答题”类错误，页面停留在当前卷。

### M05 统计

1. 我的问卷 → 演示问卷 → 统计结果；
2. 期望总答卷数 ≥3；
3. 单选显示每个选项人数和百分比；
4. 数字显示平均值/最小值/最大值；
5. 文本显示原文；
6. 点击“只看本题”，期望只显示该题。

### M06 登录限制

1. 用 API 创建 `allowAnonymous=false` 的已发布问卷；
2. 未登录打开 `/survey/:code`；
3. 期望只显示“需要登录后填写”，不显示题目。

### M07 关闭与截止（API/手工）

1. 关闭问卷；
2. 打开链接，期望“问卷已关闭”；
3. 设置过去时间后发布，期望“截止时间已过”。

## 5.7 如何复现

```bash
# 1. 安装依赖
pnpm install

# 2. 确保本机有 mongod；默认路径不匹配时：
#    Windows PowerShell:
$env:MONGOD_BINARY = "D:\Program Files\MongoDB\Server\9.0\bin\mongod.exe"

# 3. 运行全部测试（自动启动临时 mongod）
pnpm test

# 4. 静态语法检查
pnpm check

# 5. 启动应用 + 浏览器 E2E
pnpm db:init
pnpm seed
pnpm start            # 终端 1
pnpm test:e2e        # 终端 2
```

## 5.8 测试局限

- 浏览器 E2E 依赖本机 Chrome/Edge，并且需要允许启动浏览器子进程；未做多浏览器兼容性矩阵。
- 并发重复填写（`allowMultiple=false`）未做压力测试；当前实现是“先查后插”，报告已列为边界。
- 测试依赖本机 `mongod`；CI 环境需安装或通过 `MONGOD_BINARY` 指定。
- UI E2E 覆盖主流程，不覆盖所有边界组合；边界组合由 81 个 API/单元测试覆盖。
