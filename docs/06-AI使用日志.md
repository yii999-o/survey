# 六、AI 使用日志与使用说明

> **真实性说明**
>
> 本项目实际使用的是 **DeepSeek Harness 编程代理（deepseek-flash）**，没有使用 ChatGPT、Copilot、Cursor 等其他工具。
>
> 用户把课程项目完整需求作为一条初始提示词交给代理；代理在会话中自行拆分任务、读取仓库、修改代码、运行测试。下表的“提示词/指令”列，记录的是**实际初始需求**或代理为完成该需求而执行的子任务指令，不是事后虚构的多轮人类对话。所有“修改/验证”列都以仓库中的最终代码和实际测试结果为准。

## 6.1 工具与工作方式

| 项 | 内容 |
| --- | --- |
| 工具 | DeepSeek Harness（Web GUI / 编程代理） |
| 模型 | deepseek-flash |
| 交互方式 | 自然语言需求 → 代理读取文件 → 修改代码 → 运行 Node/Jest → 根据失败继续修复 |
| 代码审查 | 代理自检 + 实际运行 `pnpm test`、`pnpm check`、启动服务做 API 端到端验证 |
| 未使用 | 未使用问卷系统现成框架；未使用关系数据库；未复制网络上的完整项目 |

## 6.2 提示词与产出日志

### AI-01 初始需求输入

**提示词（原始需求，节选）**：

```text
项目：基于 MongoDB 的问卷系统开发
本项目要求开发一个简化版的在线问卷系统，功能类似于“问卷星”或 Google Forms。
系统应允许注册用户创建问卷，并通过 URL 分发问卷，其他用户可以填写问卷，系统可以统计问卷结果。
...
初始用户需求：
一、用户账号功能 ...
二、问卷创建与管理 ...
三、问卷中的题目 ...
四、题目跳转功能 ...
五、填写问卷 ...
六、查看统计结果 ...
```

**AI 产出**：

- 读取仓库，发现已有脚手架：`src/models`、`src/routes`、部分页面；
- 发现 `src/services/junmpEngine.js` 和大量页面/测试为空文件；`package.json` 指向不存在的 `src/server.js`，实际只有拼写错误的 `src/sever.js`；
- 制定任务拆分：共享引擎 → 模型/路由 → 前端 → 测试 → 文档。

**是否修改**：是。后续所有条目都是在此需求上继续修改，没有推倒重来。

### AI-02 设计并实现共享跳转/校验引擎

**子任务指令**：

```text
把跳转和校验做成前后端共用的一份纯逻辑，支持单选、多选、数字条件；
跳转目标只能向后，goto=null 结束；被跳过的必答题不校验；路径外答案拒绝。
```

**AI 产出**：

- 新建 `shared/survey-engine.js`（UMD，浏览器/Node 共用）；
- `matchJump`、`walkPath`、`validateAnswer`、`validateSubmission`、`validateSurveyDefinition`；
- `src/services/jumpEngine.js`、`src/services/validation.js` 作为服务端薄封装；
- 浏览器 `fill.html` 直接加载 `/shared/survey-engine.js`。

**是否修改**：是。审查时补充了：

- 运行期 `visited` 集合防循环（即使数据校验已禁止回跳）；
- Unicode 码点长度，避免 emoji 被算成两个字符；
- 原始输入中的非法数字/布尔/数组拒绝，而不是静默转为 null；
- 重复 qid 检查。

### AI-03 设计 MongoDB Schema 与索引

**子任务指令**：

```text
按三个集合设计：users、surveys、responses；
题目和跳转嵌入 survey，答案嵌入 response；说明为什么适合 MongoDB；
补充 JSON Schema 校验器和索引。
```

**AI 产出**：

- `src/models/User.js`、`Survey.js`、`Response.js`；
- `scripts/init-db.js`：MongoDB `$jsonSchema` + 索引；
- `src/services/stats.js`：`$unwind` + `$group` 聚合；
- 文档 `docs/02-数据库设计.md`。

**是否修改**：是。审查时：

- 删除 `username` 字段 `unique: true` 与 `schema.index` 的重复索引；
- 为 `shareCode` 增加唯一索引和碰撞重试；
- 明确 `allowMultiple=false` 无法用全局唯一索引实现（匿名/多次填写冲突），改为应用层查询并写入已知边界；
- 增加 `visitedPath`、`schemaVersion`、`publishedAt/closedAt`。

### AI-04 实现认证与问卷管理 API

**子任务指令**：

```text
实现注册、登录、JWT、我的问卷、创建/更新/发布/关闭/删除、统计、公开链接；
只允许 owner 操作；发布后不能改题目结构。
```

**AI 产出**：

- `src/routes/auth.js`、`surveys.js`、`responses.js`；
- `src/middleware/auth.js`、`error.js`；
- `src/app.js`、`src/server.js`；
- 路由顺序、错误码、owner 校验、发布锁、截止时间判断。

**是否修改**：是。主要修正：

- 原 `src/sever.js` 拼写错误 → 新增 `src/server.js`，package 指向正确；
- 原 `src/routes/surveys.js` 中 `/:id` 在 `by-code` 前可能导致路由歧义的风险 → 将 `by-code` 放到 `/:id` 之前；
- 原 `res.json` 创建返回 200 → 改为 201；
- 增加 `allowMultiple`、`publishedAt/closedAt`、`responseCount`；
- 增加 `/api/surveys/:id` 详情、DELETE 草稿、`/api/auth/me`、健康检查。

### AI-05 补全前端页面

**子任务指令**：

```text
不要只做接口。补全登录、我的问卷、编辑、填写、统计页面；
编辑页要能配置题型/选项/校验/跳转；填写页要按跳转动态显示题；
不要用 innerHTML 直接插入用户输入。
```

**AI 产出**：

- `public/login.html`、`dashboard.html`、`edit.html`、`fill.html`、`stats.html`、`404.html`；
- `public/css/app.css`、`public/js/common.js`；
- 编辑页用 DOM API 构建题目卡片、选项、跳转规则；
- 填写页只渲染一次，通过 `.hidden` 控制跳转，避免输入时重渲染丢焦点。

**是否修改**：是。修正：

- 原填写页 `setAns` 每次输入都 `renderForm()`，文本框会丢焦点 → 改为只更新可见性；
- 原编辑页大量内联 `onclick`/字符串拼接，存在引号/XSS 风险 → 改为 `addEventListener` + `textContent`；
- 原 dashboard 的“新建问卷”链接到没有 id 的编辑页会跳回 → 编辑页支持无 id 新建；
- 加入 `allowMultiple` 选项、发布后锁定 UI、复制链接。

### AI-06 编写并运行测试

**子任务指令**：

```text
至少覆盖创建问卷、添加题目、跳转、校验、提交、统计；
使用 Jest + Supertest；测试要能重复运行，不污染开发库。
```

**AI 产出**：

- `tests/auth.test.js`、`survey.test.js`、`submission.test.js`、`stats.test.js`、`jump.test.js`、`validation.test.js`；
- `tests/helpers/db.js`：临时 mongod + 随机端口 + 清理；
- 70 个测试，全部通过；
- `scripts/e2e-ui.js`：用本机 headless Chrome 验证登录、统计、编辑发布、跳转填写、登录限制，并截图。

**是否修改**：是。实际踩坑与修正：

1. 测试 helper 的 `require('../src/app')` 路径错误（helper 在 `tests/helpers/`）→ 改为 `../../src/app`；
2. 最初使用 `mongodb-memory-server@10`，它无法识别本机 MongoDB 9 的版本输出 → 改为自行 spawn 本机 mongod，随机端口，`stdio: 'ignore'`，测试后清理；
3. 最初 `beforeEach` 只清集合，但用户唯一索引仍在 → 改成清空所有集合，保持索引；
4. Jest 在 Windows 下通过 pnpm 符号链接执行时出现依赖解析问题 → 在 `pnpm-workspace.yaml` 设置 `nodeLinker: hoisted`；
5. 4xx 错误在测试中打印大量堆栈 → 错误中间件只对 5xx 打印。

## 6.3 AI 做对了什么

1. **快速把需求转成可执行模块**：引擎、模型、路由、页面、测试一次成型，节省大量样板代码时间。
2. **共享逻辑思路正确**：把跳转/校验抽到 UMD 模块，避免前后端两套规则；这是本项目最重要的架构决策之一。
3. **测试驱动修复有效**：70 个测试暴露了路径、状态码、跳转边界、聚合口径等问题，修复后可回归。
4. **文档结构化**：按评分点组织数据库、API、测试、AI 日志，便于答辩。

## 6.4 AI 做错了什么（真实记录）

| 问题 | 表现 | 发现方式 | 修正 |
| --- | --- | --- | --- |
| 文件名拼写 | `src/sever.js`、`src/services/junmpEngine.js` | 读取目录、启动失败 | 新增正确文件，package 指向 `server.js` |
| 页面为空 | 多个 HTML 只有空文件或半成品 | 读取文件 | 重写页面 |
| 跳转引擎缺失 | `validation.js` 引用不存在的 `jumpEngine` | Node 运行/测试 | 新建共享引擎 |
| 重渲染丢焦点 | 填写页每次输入都重建 DOM | 代码审查 | 只切换可见性 |
| 测试 helper 路径 | `../src/app` 少一层 | Jest 报 Cannot find module | 改为 `../../src/app` |
| 测试数据库选型 | `mongodb-memory-server` 不识别 MongoDB 9 | 测试启动失败 | 改为本机 mongod + 随机端口 |
| pnpm 链接问题 | Windows 下 mongoose 依赖解析失败 | `node scripts/init-db.js` 报错 | `nodeLinker: hoisted` |
| 重复索引 | username 上同时 `unique` 和 `schema.index` | Mongoose 警告 | 删除重复索引 |
| 语法错误 | 填写页 401 分支多一个 `)` | `pnpm check` | 修正 |
| 文档与实现偏差 | 早期接口返回 200/字段名不同 | 对照最终代码 | 统一为 201/最终字段 |

这些问题说明：**AI 生成的代码不能直接当作正确结果**，必须通过运行、测试和代码审查验证。

## 6.5 自己设计/自己修改的部分

在 AI 输出基础上，开发者（提交者）主导/确认了以下设计：

1. **数据库三集合边界**：用户、问卷、答卷分开；题目嵌入问卷、答案嵌入答卷。
2. **发布后冻结题目结构**：避免历史答卷与题目语义不一致；这是 AI 初版没有明确做的约束。
3. **跳转只允许向后**：用定义校验从源头排除循环，运行期再做兜底。
4. **路径外答案拒绝**：服务端不信任前端“隐藏题目”，防止绕过跳转提交。
5. **统计口径**：多选百分比按“回答该题人数”计算，明确可能超过 100%；不持久化计数器。
6. **重复填写边界**：承认匿名无法可靠去重，`allowMultiple=false` 只对登录用户生效。
7. **测试策略**：不依赖外部下载的 mongod 二进制，使用本机 mongod 临时实例，保证可重复。
8. **安全细节**：owner 校验、统一 404、密码哈希、JWT、内容长度限制、前端转义。

## 6.6 使用 AI 的规范（本项目遵守）

1. **不把 AI 输出直接当最终答案**：每个模块都要运行/测试；
2. **不伪造测试结果**：文档中的 70 个测试是实际运行结果；
3. **不隐瞒 AI 错误**：上表记录了真实的失败与修复；
4. **不让 AI 决定不可验证的结论**：数据库设计理由、统计口径、已知边界由开发者确认；
5. **保留可追溯性**：关键逻辑集中在 `shared/survey-engine.js`，便于审查“AI 到底生成了什么”。

## 6.7 对 AI 使用的总结

AI 在本项目中主要承担“高强度编码助手”角色：生成样板、补全页面、写测试、写文档。它显著缩短了开发时间，但也产生了文件名拼写、路径、依赖、边界条件等错误。真正保证项目可提交的，是**运行测试、对照需求检查、修正设计**，而不是提示词本身。

如果重新做一次，我会：

- 先手写数据库设计和跳转语义，再让 AI 按设计实现；
- 每个模块先写测试再让 AI 补实现；
- 对 AI 生成的依赖/脚本在本机实际运行，不假设它能工作；
- 让 AI 只改一个模块，减少跨文件连锁错误。
