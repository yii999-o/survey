# 四、关键逻辑说明

## 4.1 共享逻辑引擎

文件：`shared/survey-engine.js`

它用 UMD 包装，同时支持：

- Node.js：`require('../../shared/survey-engine')`
- 浏览器：`<script src="/shared/survey-engine.js">`，挂载 `window.SurveyEngine`

这样做的原因：跳转和校验是**最容易前后端不一致**的部分。如果浏览器、服务端各写一份，修一处忘一处就会导致“页面能填、提交失败”或“页面隐藏了某题、服务端仍要求必答”。

导出函数：

| 函数 | 作用 |
| --- | --- |
| `normalizeQuestion` | 规范化题目字段 |
| `sortQuestions` | 按 `order` 排序 |
| `matchJump` | 判断单条跳转条件是否命中 |
| `walkPath` | 根据答案计算完整答题路径 |
| `validateAnswer` | 单题答案校验 |
| `validateSubmission` | 整卷校验（路径 + 必答 + 路径外答案） |
| `validateSurveyDefinition` | 创建/修改/发布时的题目结构校验 |

## 4.2 跳转规则数据模型

每条规则：

```javascript
{
  when: { ... },
  goto: "q3" | null
}
```

- `when` 是条件对象，只能有一个条件字段（校验器强制）；
- `goto` 是目标题目的 qid；`null` 表示提交后直接结束；
- `jumps` 数组有顺序，**第一条命中的规则生效**。

### 支持的条件

| 题型 | `when` | 说明 |
| --- | --- | --- |
| single | `{ option: "A" }` | 选中 A |
| multi | `{ includes: "A" }` | 选中项包含 A |
| multi | `{ countAtLeast: 2 }` | 选择数量 ≥ 2 |
| multi | `{ countAtMost: 3 }` | 选择数量 ≤ 3 |
| multi | `{ countEquals: 2 }` | 选择数量 = 2 |
| number | `{ op: ">=", value: 18 }` | 数值 ≥ 18；op 支持 `> >= < <= ==` |
| text | 不支持 | 第一阶段需求未要求按文本内容跳转 |

### 为什么只允许向后跳

如果允许 `goto` 指向当前题或前面题，可能出现：

```text
q1 --A--> q3 --B--> q1 --A--> q3 ... 死循环
```

本系统在**定义校验阶段**直接拒绝 `targetIndex <= currentIndex`，因此正常数据不可能形成循环。运行期 `walkPath` 仍用 `visited` 集合兜底，防止旧数据/手工改库造成死循环。

这是有意的限制：问卷通常按页向后流转，不允许回跳足以满足需求，同时让实现可证明终止。

## 4.3 路径计算算法

`walkPath(survey, answers)`：

```text
questions = sortByOrder(survey.questions)
indexByQid = map(qid -> 下标)
i = 0
path = []
visited = set()

while 0 <= i < questions.length:
    q = questions[i]
    if q.qid in visited: 报错“循环”
    visited.add(q.qid); path.add(q.qid)

    for rule in q.jumps (按数组顺序):
        if matchJump(rule, answers[q.qid]):
            if rule.goto == null: 结束（terminated = true）
            if rule.goto 不存在: 报错
            if 目标下标 <= i: 报错“回跳”
            i = 目标下标
            continue outer
    i = i + 1

return { path, terminated, error }
```

关键点：

- **没有答案时不会命中条件**：例如 q1 未答，所有 `when` 都不命中，路径继续到下一题；但提交时必答校验会拦住。
- **路径只影响“哪些题要答”**，不影响“哪些答案被保存”：提交时只保存路径上的答案。
- **被跳过的必答题不再校验**：这是需求“如果第 1 题选 A 跳到第 5 题，则第 2–4 题不应强制作答”的直接实现。

### 示例

```text
q1 单选：A → q3，B → q2
q2 文本（必答）
q3 数字
q4 文本

答案 q1=A  => path [q1, q3, q4]，q2 不校验
答案 q1=B  => path [q1, q2, q3, q4]
答案 q1=A 且 q3>=18 有规则 → q4：path [q1, q3, q4]
```

## 4.4 校验体系

校验分为五层，越靠后越可信：

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 1. HTML 约束 | 填写页 | `required`、`maxlength`、`min/max`、`step`，改善体验 |
| 2. 浏览器即时校验 | `fill.html` + `SurveyEngine.validateAnswer` | 提交前提示，滚动到错误题 |
| 3. 服务端单题校验 | `validateAnswer` | 选项合法性、多选数量、文本长度、数字范围/整数 |
| 4. 服务端整卷校验 | `validateSubmission` | 路径、必答、路径外答案、重复 qid |
| 5. 数据库校验 | Mongoose + MongoDB `$jsonSchema` | 字段类型、必填、枚举、结构 |

### 单题规则

| 题型 | 规则 |
| --- | --- |
| single | 值必须属于该题 options 的 key；必答不能为空 |
| multi | 必须是数组、无重复、所有 key 合法；`minSelect`/`maxSelect` |
| text | 必须是字符串；按 Unicode 码点计长度；`minLength`/`maxLength` |
| number | 必须是有限数字；`integerOnly` 用 `Number.isInteger`；`min`/`max` |

### 整卷规则

1. `answers` 必须是数组；
2. 每个元素必须有 qid，且 qid 不重复、存在于问卷；
3. 用答案计算路径；
4. 路径上的每道题按题型校验；空值且非必答则跳过（不写入 answers）；
5. 提交了路径外题目的答案 → `400`，防止绕过跳转；
6. 返回规范化答案和 `path`。

### 题目定义校验

`validateSurveyDefinition` 在创建/更新/发布时检查：

- 至少 1 题（发布时）；最多 100 题；
- qid 唯一，1–32 位字母/数字/下划线/短横线；
- type 合法；
- 标题非空、≤200 字；
- 单选/多选至少 2 个选项，key 不重复、label 非空；
- 文本/数字题不应有 options；
- 多选 min/max 为整数、1 ≤ min ≤ max ≤ 选项数；
- 文本 min/max 为 0–10000 的整数，min ≤ max；
- 数字 min/max 为有限数且 min ≤ max；
- jumps 最多 50 条；
- 每条规则只能有一个条件，条件字段与题型匹配，引用的选项存在；
- `goto` 必须存在且只能在当前题之后；
- 文本题不允许配置跳转；
- 原始输入中的非法数字/布尔/数组类型会被拒绝，而不是静默修正。

## 4.5 多选跳转的特殊说明

多选题的“包含选项”和“选择数量”是两类不同语义：

- `includes: "A"`：只要选了 A 就跳，哪怕还选了 B/C；
- `countAtLeast: 2`：选几个都行，只要数量 ≥ 2；
- `countAtMost: 1`：选 0 或 1 个时跳。注意：空答案不会命中任何规则（未答时按顺序走），所以“最多 1 个”不会把未答误判为命中。

当前 UI 每次只配置一个条件；如果将来需要“包含 A 且至少 2 个”，需要扩展 `when` 为多条件（第二阶段可做）。

## 4.6 统计实现

文件：`src/services/stats.js`

### 聚合管道

```javascript
[
  { $match: { surveyId } },
  { $unwind: "$answers" },
  { $match: { "answers.qid": { $in: qids } } },
  { $group: {
      _id: { qid: "$answers.qid", value: "$answers.value" },
      count: { $sum: 1 }
  }}
]
```

然后按题型组装：

- **单选**：每个选项 key 初始化 0，按分组值累加；`totalAnswers` = 该题分组 count 之和。
- **多选**：分组值是数组；遍历数组，每个选项累加该组的 count。`totalAnswers` 仍是回答该题的人数；百分比 = 选项人数 / 回答人数，合计可超过 100%，文档中明确说明。
- **数字**：把相同值的 count 展开成值列表，计算 average/min/max。
- **文本**：展开为原文列表。

### 为什么不在 Survey 上存统计计数

如果每次提交都 `$inc` 统计字段：

- 并发提交、失败重试可能导致计数漂移；
- 修改/删除答卷（未来）需要同步回滚；
- 统计维度增加（按题、按时间、按选项）时无法复用。

实时聚合在单问卷数据量下足够快；数据量增大后可增加缓存或按天物化。

### 统计口径

- `totalResponses`：问卷全部答卷数，包含跳过某题的答卷；
- `totalAnswers`：实际回答了该题的人数；
- 单选 `counts` 合计 = `totalAnswers`；
- 多选 `counts` 合计 ≥ `totalAnswers`（可能重复计人）；
- 文本/数字的 `values` 只包含实际提交的值，不含空值。

## 4.7 发布、关闭与截止

### 发布

`POST /publish`：

1. owner 校验；
2. 已关闭 → `409`；已发布 → 幂等返回；
3. `validateSurveyDefinition`（至少 1 题、跳转合法）；
4. 截止时间已过 → `400`；
5. `status=published`、`publishedAt=now`、`closedAt=null`。

发布后 `PUT` 带 `questions` → `409`。这样历史答卷的 qid 语义不会变。

### 关闭

`POST /close`：仅已发布可关闭；`status=closed`，`closedAt=now`。填写 GET/POST 均返回 `410`。

### 截止

读取和提交时都判断 `deadline && now > deadline` → `410`。没有后台定时任务，因此“到期”是**请求时判断**，简单可靠；代价是数据库里的 `status` 不会自动变 `closed`，这是有意的（避免定时任务复杂度）。

## 4.8 匿名与重复填写

### 匿名

- `allowAnonymous=true`：无 token 也能读取和提交；`respondentId=null`。
- `allowAnonymous=false`：无 token 在 `GET /by-code` 就返回 `401`，不暴露题目；提交也再次检查。

### 重复填写

- `allowMultiple=true`（默认）：同一账号可多次提交，每次一份 Response。
- `allowMultiple=false`：登录用户提交前查 `{surveyId, respondentId}`，已存在返回 `409`。
- 匿名用户无法可靠识别身份（IP/UA 不可靠且有隐私问题），因此匿名场景不强制去重；这一点在 README 和报告中如实说明。

## 4.9 并发与一致性

- 每次提交创建独立 Response 文档，多人同时填写不会互相覆盖。
- `shareCode` 有唯一索引；创建时若碰撞（概率极低）重试 5 次。
- 重复填写检查是“先查后插”，两个并发请求理论上都可能通过；第一阶段未加分布式锁。要严格保证，可对 `allowMultiple=false` 的问卷加唯一索引/事务，但需要把“是否允许多次”编码进索引条件，复杂度较高。报告中列为已知边界。
- 发布/关闭是单文档更新，原子性由 MongoDB 保证。

## 4.10 前端填写页的可见性处理

`fill.html` 不在每次输入时重建 DOM，而是：

1. 首次渲染所有题目；
2. 每次答案变化调用 `walkPath`；
3. 给不在路径上的题加 `.hidden`；
4. 提交时只收集路径上的非空答案。

这样做避免文本框输入时因重渲染丢失焦点，也让跳转后的“回退”更容易：用户改回原选项时，原题卡片重新显示，之前填的值还在。

## 4.11 错误提示策略

- 浏览器：显示第一条错误，滚动并聚焦到对应题；
- 服务端：返回 `400` + 人类可读中文；题目定义错误可带 `details` 数组；
- 4xx 不打印堆栈；5xx 记录日志；
- 前端所有用户内容用 `textContent` 或 `escapeHtml`，避免把标题/选项当 HTML 执行。
